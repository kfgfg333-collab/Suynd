# Suynd — личный музыкальный плеер в Telegram

Mini App и бот, доступные только вам. Главный сценарий: вы пишете название песни или исполнителя — Suynd ищет полную версию в разрешённых источниках, проверяет, что звук действительно отдаётся, и показывает **один лучший результат** с кнопкой «Слушать». Если полной версии нигде нет, приложение так и говорит и даёт официальные ссылки (Deezer, Spotify, Яндекс Музыка).

Что ещё есть:

- **Моя волна**: бесконечный поток, который подстраивается под лайки и 👍/👎. Режимы «Знакомое / Микс / Новое», настроение «Спокойное / Энергичное». Треки за последние 3 дня не повторяются.
- **Любимые, история за 3 дня, плейлисты** с обложкой-коллажем и перетаскиванием треков.
- **Мои файлы**: отправьте боту mp3/m4a/flac — трек будет играть целиком, с обложкой из тегов.
- **Скачивание для офлайна** и **отправка файла в чат** — только там, где это разрешено: ваши файлы, CC-записи (Internet Archive, Openverse, Jamendo с разрешением автора), треки Audius с разрешением автора.
- **Артисты и альбомы** (вкладки поиска) из каталога Deezer и Audius; у треков каталога — «Найти полную».
- **Радар релизов**: раз в час проверяет новинки артистов, на которых вы подписаны, и пишет в бота.
- Управление с экрана блокировки и с наушников (Media Session), виброотклик, свайп по треку — в очередь.

```
server/   API (Fastify + SQLite/Drizzle), бот (grammY), фоновые задачи (node-cron)
web/      Mini App (React + Vite + TypeScript + Tailwind + Framer Motion + Zustand)
docs/     PLAN.md: архитектура, схема БД, поиск, волна
```

## Источники

Только официальные бесплатные API с правом на воспроизведение. Звук и обложки идут **через ваш сервер**, поэтому приложение работает, даже если домен источника заблокирован у вас в сети.

| Источник | Что даёт | Полный трек | Скачивание | Ключ |
|---|---|---|---|---|
| Audius | независимые артисты, электроника, хип-хоп; стриминг разрешён условиями API | ✅ | если автор разрешил | не нужен |
| Internet Archive | только записи под Creative Commons и в общественном достоянии: классика, концерты, нетлейбл | ✅ | ✅ (лицензия) | не нужен |
| Jamendo | 600 тыс.+ треков под CC | ✅ | если автор разрешил | бесплатный `JAMENDO_CLIENT_ID` |
| Openverse | открытый индекс CC-аудио (Jamendo, Wikimedia Commons); анонимный API медленный, поэтому источник необязательный: ждём 5 с | ✅ | ✅ (лицензия) | не нужен |
| Мои файлы | что вы загрузили сами: через бота, с телефона или по ссылке | ✅ | ✅ | — |
| Deezer | **только каталог**: метаданные, обложки, артисты, альбомы, эталон для сравнения и официальная ссылка. Звук Deezer — 30-секундные превью, в Suynd он не играет | — | ❌ | не нужен |

Spotify, Apple Music, Яндекс Музыка и т.п. не используются как источник звука: их условия этого не разрешают. Только ссылки на их официальные страницы.

## Как работает поиск трека

1. Запрос очищается (управляющие символы, пробелы, до 100 символов).
2. Параллельно: каталог Deezer (с вариантами транслитерации — «Милано Скам» → «Milano Skam») и все подключённые источники. У каждого источника свой тайм-аут; не ответил или ответил ошибкой — пропускается на 30 с, остальные работают.
3. Если запрос называет конкретную песню из каталога (есть слова названия и, если указан, исполнитель), она становится **эталоном**: кандидаты сравниваются по названию, исполнителю, длительности (±12% или ±15 с) и версии. Ремикс, кавер, live, sped up, slowed, утечка, инструментал, караоке и т.п. не выдаются за оригинал. Если исполнитель не назван («lofi chill», «Скам»), подходящая запись подбирается по словам запроса.
4. Превью и обрывки короче 45 с отбрасываются. Одна и та же запись из разных источников склеивается.
5. **Поток проверяется**: сервер запрашивает первые байты аудио (статус 200/206 и звуковой тип). Не отдаёт — берётся следующий кандидат. Ссылка без работающего звука результатом не считается.
6. Та же запись из других источников приходит как запасные (`alternates`): если основной поток не заиграет, плеер сам переключится на следующий, каждый вариант — один раз.
7. Результат кэшируется на 10 минут (пустой — на 2), одинаковые одновременные запросы ждут один поиск.

Для популярных треков крупных лейблов полной версии в открытых источниках обычно нет — например, «Scally Milano — Скам». Тогда Suynd показывает, что нашлось в каталоге, и ссылки на официальные сервисы. Превью или чужую версию он не подставляет.

**Никаких превью.** В плеер, волну, избранное, историю, плейлисты и офлайн попадают только подтверждённые полные треки. Плеер и загрузчик дополнительно сверяют фактическую длительность звука: обрезок не играет и не сохраняется.

**Кэш аудио.** Полные файлы из CC-источников (Internet Archive, Openverse, Jamendo) и ваши файлы при первом прослушивании сохраняются на диск сервера: повтор и скачивание идут с диска. В кэш попадает только файл с подтверждённой длительностью; старые удаляются, когда кэш превышает `AUDIO_CACHE_MB`. Треки Audius не кэшируются.

**Explicit-версии:** если в каталоге есть и цензурная (clean / radio edit), и explicit-версия, эталоном становится explicit. Такие треки помечены значком **E**.

**Импорт:** «Коллекция → Мои файлы → Загрузить файлы / По ссылке». Файл проверяется: формат, звуковая дорожка, длительность, размер до 20 МБ. Веб-страница вместо файла, повреждённый файл и внутренние адреса отклоняются.

## API (кратко)

Все маршруты, кроме `/health` и `/api/auth`, требуют `Authorization: Bearer <токен сессии>` (для `<audio>` и картинок — `?t=`). Ошибки всегда в одном формате: `{"error":"error","message":"понятный текст","code":"…"}` (`code` — если есть).

| Маршрут | Что делает |
|---|---|
| `POST /api/auth` | проверка Telegram initData → токен сессии |
| `GET /api/search?q=…&type=tracks` | `{ query, mode, best, more, catalog, links, partial }` — один лучший проверенный трек (`best.alternates` — запасные источники) |
| `GET /api/search?q=…&type=artists\|albums` | `{ items }` — артисты/альбомы Deezer и Audius |
| `GET /api/tracks/:id/full` | полная версия трека каталога Deezer: `{ track, checked }` |
| `GET /api/stream/:id` | аудио через сервер, с HTTP Range (перемотка) |
| `GET /api/download/:id`, `POST /api/send/:id` | скачать / отправить в чат — только где разрешено |
| `GET /api/sources` | какие источники подключены (без ключей) |
| `GET /health` | `{"ok":true}` |

Логи — JSON-строки (`event: search | provider | provider_error | full_version`) с временем, источником и длительностью; текст запроса заменён коротким хэшем, ключи API вырезаются.

2. Аккаунты на [Vercel](https://vercel.com) (для фронтенда) и [Railway](https://railway.com) (для сервера и бота). Войти в оба можно через GitHub.

## Шаг 1. Создайте бота в @BotFather

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Придумайте имя (например, `Мой плеер`) и username, который заканчивается на `bot` (например, `my_suynd_bot`).
3. BotFather пришлёт **токен** вида `1234567890:AAH...`. Это пароль от бота: никому его не показывайте и не выкладывайте в GitHub.

## Шаг 2. Узнайте свой Telegram ID

1. Откройте [@userinfobot](https://t.me/userinfobot) и нажмите «Start».
2. Он пришлёт ваш **Id**: число вроде `123456789`. Это значение для `ALLOWED_USER_ID`.

Пускать будет только этот ID. Сервер проверяет подпись Telegram (initData) по токену бота, поэтому подделать вход нельзя.

## Шаг 3. Запуск на своём компьютере (по желанию)

```bash
# 1) сервер и бот
cd server
cp .env.example .env        # затем откройте .env и впишите BOT_TOKEN и ALLOWED_USER_ID
npm ci
npm run dev                 # API на http://localhost:3000, бот запустится автоматически

# 2) во втором терминале: фронтенд
cd web
cp .env.example .env        # VITE_API_URL=http://localhost:3000
npm ci
npm run dev                 # откройте http://localhost:5173
```

Внешних программ не нужно: только Node.js 22. Зависимости ставятся строго по lock-файлам (`npm ci`).

Запуск сервера в Docker:

```bash
docker build -t suynd-server server
docker run --env-file server/.env -p 3000:3000 -v suynd-data:/data suynd-server
```

Чтобы открыть приложение в обычном браузере без Telegram, поставьте в `server/.env` значение `DEV_AUTH_BYPASS=true`. Эта настройка работает только локально и в продакшене отключается сама.

> ⚠️ Один и тот же бот нельзя запускать в двух местах сразу: Telegram выдаст ошибку `409 Conflict`. Если бот уже работает на Railway, а вы хотите проверить что-то локально без него, добавьте в `server/.env` строку `BOT_DISABLED=true`.

## Шаг 4. Деплой сервера и бота на Railway

1. Зайдите на [railway.com](https://railway.com), нажмите **New Project → Deploy from GitHub repo** и выберите этот репозиторий.
2. Откройте созданный сервис → **Settings**:
   - **Root Directory** = `server`;
   - в папке `server` лежит `Dockerfile` (Node.js 22, без других программ), и Railway соберёт сервер по нему. Команды сборки и запуска трогать не нужно.
3. **Подключите диск, чтобы база не стиралась.** В проекте нажмите **+ New** (или правой кнопкой по холсту) → **Volume**, выберите ваш сервис и укажите Mount Path `/data`.
4. Откройте вкладку **Variables** и добавьте переменные:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | токен от BotFather |
   | `ALLOWED_USER_ID` | ваш ID из шага 2 |
   | `SESSION_SECRET` | любая длинная случайная строка, например 40 случайных букв и цифр |
   | `DATA_DIR` | `/data` |
   | `NODE_ENV` | `production` |
   | `WEBAPP_URL` | пока оставьте пустым, заполните в шаге 6 |
   | `JAMENDO_CLIENT_ID` | необязательно: ключ с [devportal.jamendo.com](https://devportal.jamendo.com) (Create app) |
   | `AUDIO_CACHE_MB` | необязательно: место под кэш полных аудиофайлов на сервере, по умолчанию `1024`; `0` — выключить |

5. **Settings → Networking → Generate Domain.** Railway выдаст адрес вида `https://suynd-production.up.railway.app`. Проверьте его: если открыть `https://…railway.app/health`, должно появиться `{"ok":true}`.

> Про расходы: внешние сервисы Suynd бесплатны (Audius, Internet Archive, Openverse, Deezer — без ключей; Jamendo — бесплатный ключ). Платить можно только за хостинг: фронтенд на Vercel Hobby бесплатен, сервер с ботом на Railway обычно укладывается в тариф Hobby (около $5 в месяц с включённым объёмом использования) — это в пределах €10. Railway даёт пробные кредиты, а условия бесплатного тарифа периодически меняются, поэтому проверьте актуальные на [railway.com/pricing](https://railway.com/pricing). Можно использовать и **Render** (Web Service, Root Directory `server`, Start Command `npm start`), но у бесплатного Render нет постоянного диска: база будет стираться при каждом перезапуске, а через 15 минут простоя сервер засыпает вместе с ботом. Поэтому Railway с Volume подходит лучше.

## Шаг 5. Деплой фронтенда на Vercel

1. На [vercel.com](https://vercel.com) нажмите **Add New → Project** и импортируйте этот репозиторий.
2. **Root Directory** = `web`. Vercel сам определит фреймворк Vite.
3. В **Environment Variables** добавьте `VITE_API_URL` = адрес из Railway, без слэша на конце (например, `https://suynd-production.up.railway.app`).
4. Нажмите **Deploy**. Получится адрес вида `https://suynd.vercel.app`.

## Шаг 6. Соедините всё вместе

1. Вернитесь в Railway → **Variables** и впишите `WEBAPP_URL` = адрес Vercel (например, `https://suynd.vercel.app`). Сервис перезапустится сам.
2. Откройте своего бота в Telegram и отправьте `/start`. Появятся кнопка «🎧 Открыть плеер» и кнопка меню «Плеер» слева от поля ввода: бот ставит её сам.
3. (По желанию) Чтобы у приложения была красивая ссылка `t.me/ваш_бот/app`: в @BotFather отправьте `/newapp`, выберите бота, загрузите картинку 640×360, укажите URL Vercel и короткое имя, например `app`.

Готово 🎉 Если поменяете код, отправьте его в GitHub командой `git push`: Vercel и Railway пересоберут проект сами.

## Как пользоваться

| Что | Как |
|---|---|
| Добавить свою музыку | отправьте боту аудиофайл; он появится в «Коллекция → Мои файлы» |
| Лайк | ♥ в плеере или в меню «⋯» у любого трека |
| В очередь | смахните трек вправо или выберите в меню «⋯» |
| Полноэкранный плеер | нажмите на мини-плеер или смахните его вверх; закрывается свайпом вниз |
| Сменить трек | смахните обложку в плеере влево или вправо |
| Порядок очереди и плейлиста | перетащите трек за ⋮⋮ |
| Подписка на артиста | страница артиста → «Следить»; `/radar` в боте проверяет новинки сразу |
| Скрыть артиста из волны | 🚫 в плеере волны; вернуть можно в «Коллекция → Подписки» |

**Значки:** `полный` — трек целиком из полного источника. Превью Deezer в приложении не играют: если полной версии нет, поиск говорит об этом и даёт ссылки на Deezer, Spotify и Яндекс Музыку; те же ссылки есть в меню «⋯» у треков каталога.

## Ограничения, о которых стоит знать

- Telegram разрешает ботам скачивать файлы **только до 20 МБ**. Файлы больше сохранятся, и их можно переслать в чат, но плеер их не проиграет.
- Скачанное для офлайна хранится в браузере Telegram на конкретном устройстве. Если очистить кэш Telegram, оно пропадёт.
- Превью Deezer длятся 30 секунд: так устроен бесплатный API. Поэтому Deezer — только каталог, его звук в Suynd не играет.
- Открытые источники — это независимая и CC-музыка. Хитов крупных лейблов в них обычно нет, и Suynd честно об этом сообщает вместо подмены.
- Openverse без ключа часто отвечает медленно; если он не успел за 5 с, результат строится по остальным источникам.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| «Откройте через Telegram» | открывайте приложение кнопкой в боте, а не по ссылке в браузере |
| «Нет доступа» | `ALLOWED_USER_ID` в Railway совпадает с вашим ID из @userinfobot |
| «Сервер недоступен» | `VITE_API_URL` в Vercel указывает на Railway (https, без `/` на конце); после смены переменной сделайте Redeploy |
| Ошибка CORS в консоли | `WEBAPP_URL` в Railway совпадает с адресом Vercel буква в букву |
| Бот молчит | в логах Railway (Deployments → View logs) должна быть строка «Бот @… запущен»; проверьте `BOT_TOKEN` и что бот не запущен где-то ещё |
| Пропали лайки после деплоя | не подключён Volume или не задан `DATA_DIR=/data` |
| «Часть источников сейчас не ответила» | временный сбой Audius, Internet Archive или Jamendo; сервер повторит их через 30 с — нажмите «Повторить» |
| Jamendo не участвует в поиске | не задан `JAMENDO_CLIENT_ID`; проверьте `GET /api/sources` |
